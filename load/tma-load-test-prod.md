## Ограничения

- Сценарий бьёт HTTP API Mini App, не UI Telegram WebView.
- Успешные POST (HADS, ОСР, mood, allergies, pills) могут дергать Bot API (`TELEGRAM_PROXY` — это base URL Bot API). Для синтетических `telegram_id` Telegram отвечает ошибкой, но ожидание всё равно добавляет хвост.
- SQLite + один процесс API — правдоподобный источник max 7.58 s под 200 VU.
- Нет разбивки p95 по endpoint в этом выводе k6; узкое место по имени ручки не видно.

## Выводы

1. **Prod выдерживает 200 VU** по текущему SLO: ошибок нет, p95 **834 ms**.
2. Запас по надёжности большой; узкое место — **хвост**, не массовые 5xx.
3. Имеет смысл вынести sendMessage из request path и снять p95/max по группам k6 (`hads POST` vs `GET /api/me`), если понадобится следующий прогон.
